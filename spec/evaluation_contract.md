# 公开评测约定

## 评分对象

每次提交只收集：

```text
src/main/
```

提交包包含完整的 `src/main/` 文件树及逐文件摘要。Judge会先删除基线中的整个
`src/main/`，再按Manifest重建候选源码，因此文件删除和重命名能够被准确保留。
`pom.xml`、Maven配置、测试文件和评分脚本均使用Judge持有的只读版本。

## 评测组成

1. Test Case：构建、撮合、风险、账户、状态、兼容、边界和回归，单条结果为0或1。
2. Metric：固定工作负载下的吞吐、P99延迟、CPU效率和峰值内存，归一化至 `[0,1]`。
3. 硬门槛：构建失败、关键回归、状态不一致、数据破坏或完整性违规。

完整性违规、测试协议失败、Metric缺失和任一硬门槛失败，均使正式得分归零，且该产物不得进入最佳产物仓库。诊断性 `score_progress` 仅用于定位进展，不进入Reward。

吞吐由Judge根据固定交易数量和外部墙钟时间计算。候选程序打印的吞吐文本仅作为诊断信息，不能直接决定得分。

## 反馈边界

反馈可以公开测试分组、当前指标、归一化得分、回归和约束状态，但不会公开隐藏输入、随机种子、参考实现、准确修改位置或直接优化方案。

Agent只通过默认拒绝的工具策略和命令网关执行操作。工具调用轨迹用于完整性审计与最终Benchmark分析，不因调用次数或步骤数量获得额外Reward。
