# Oracle构建与质检

Oracle是任务作者持有的“任务可完成性证据”，不是唯一正确代码，也不直接参与候选代码形状比较。

## 不同任务来源

| 任务来源 | Oracle来源 |
|---|---|
| 已合并PR或Issue | 上游PR/目标提交，经去泄漏和行为测试复核后使用 |
| 原创研发需求 | 标注人员独立实现，并由另一名工程师审核 |
| 性能或资源优化 | 在冻结硬件上稳定优于基线且通过全部正确性测试的实现 |
| 黑盒重建 | 原程序的外部行为、协议和隐藏行为测试 |
| 迁移或升级 | 可成功迁移的目标版本、迁移脚本及前后兼容测试 |

## 准入要求

1. Oracle稳定通过全部强制Test Case和完整性检查。
2. No-op稳定失败，破坏正确性的实现不得获得有效分。
3. 至少一种结构不同但行为正确的替代实现不会被误拒。
4. 性能任务至少重复运行5次，记录中位数、标准差和变异系数。
5. Oracle、校准记录和审核记录必须保存在Agent不可见区域并绑定内容摘要。

当前 `oracle.patch` 仅是候选实现；在 `release_status.json` 的 `oracle_validated`
变为 `true` 前，不得将其作为正式Target来源。
